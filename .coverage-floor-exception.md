Reason: system-integration-tests is a cross-repo integration test harness (not a service
package). Its "source" is the tests/ directory itself — unit tests that exercise UTL/UAC
contracts in-process. The coverage metric measures how much of tests/ the test suite
covers, which is circular (tests cover themselves by definition). The real coverage
signal lives in the per-service repos (UTL, UAC, MTDS, etc.) that SIT exercises.
MIN_COVERAGE=2 is intentional: it ensures pytest runs and collects (non-zero), without
requiring a self-referential 70% coverage floor on a test-only repo. The system floor
(70) is a code-service gate; SIT is exempt as a pure integration harness.
